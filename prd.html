1. 产品概述

1.1 背景与痛点

当前产品管理过程中，团队通常需要使用 5-8 款不同工具来覆盖从用户调研到上线反馈的全流程。这些工具之间存在严重的信息孤岛问题：

  • 信息断层：调研团队的访谈记录需要手工整理后才能转化为需求文档，需求文档中的功能描述需要设计师重新理解后再绘制原型，每一步转换都伴随信息损耗和语义偏差。
  • 工具碎片化：用 Dovetail 做访谈分析、用 Notion 写 PRD、用 Figma 做原型、用 Jira 管开发、用 Canny 收反馈——团队需要频繁在不同平台间切换，上下文衔接成本极高。
  • AI 能力分散：虽然各环节已有 AI 工具（如 Galileo AI 生成 UI、ChatGPT 辅助写作），但这些 AI 能力彼此孤立，无法形成"调研洞察驱动文档生成、文档驱动原型设计、原型驱动开发排期"的连续智能链路。
  • 反馈闭环断裂：上线后的用户反馈难以自动回流到需求池和调研体系，导致产品迭代缺乏数据驱动，决策依赖直觉。

1.2 产品愿景

AInnoStar 旨在成为产品经理的一站式智能工作台——覆盖"调研 - 文档 - 原型 - 开发 - 反馈"全链路，以 AI 为核心驱动力，实现各环节的无缝衔接与数据流转，让产品团队从碎片化工具链中解放出来，专注于创造用户价值。

1.3 产品定位

维度 描述
产品类型 B 端 SaaS 产品管理平台
目标用户 互联网及软件行业的产品团队（5-200 人规模）
核心差异 端到端数据打通 + AI 原生驱动，覆盖产品全生命周期
商业模式 按团队人数分级订阅（免费版 / 专业版 / 企业版）

1.4 核心价值主张

  1. 一条链路：从用户调研到上线反馈，所有产出物在同一平台内流转，消除信息孤岛。
  2. AI 赋能每一环：AI 自动转录访谈、提取需求标签、生成 PRD 初稿、生成可交互原型、智能排期，大幅减少重复劳动。
  3. 反馈驱动迭代：上线后用户反馈自动聚类分析，回流到需求池，形成数据驱动的闭环。
  4. 协作透明高效：产品、设计、开发、测试在同一平台协作，需求变更实时同步，减少对齐成本。

3. 用户调研采访模块

3.1 模块概述

本模块是产品全链路的起点，负责用户调研的规划、执行、分析与洞察沉淀。通过 AI 能力实现访谈自动化转录、需求标签智能提取、用户画像自动建模，将非结构化的用户声音转化为结构化的产品输入。

3.2 核心功能清单

3.2.1 调研计划管理 [P0]

功能项 优先级 详细描述
调研项目创建 P0 支持创建调研项目，设定目标、范围、时间计划、参与人员；支持关联已有产品或需求池
访谈大纲生成 P0 AI 根据调研目标自动生成访谈大纲框架，包含开放性问题、场景探查、满意度量表等；用户可编辑调整
问卷设计与分发 P1 内置问卷编辑器（单选/多选/量表/开放题/矩阵题），支持生成分享链接或嵌入代码；回收数据自动入库
受访者管理 P0 受访者信息录入与管理，支持标签分类（用户类型/使用频次/满意度等），支持批量导入

3.2.2 访谈记录与分析 [P0]

功能项 优先级 详细描述
AI 实时转录 P0 接入语音识别引擎，支持中英文实时转录；自动区分不同说话人（Speaker Diarization）；支持上传录音文件离线转录
智能摘要生成 P0 AI 自动生成访谈摘要，提炼关键观点、用户痛点、期望功能、情感倾向；支持用户修正
需求标签提取 P0 AI 从访谈文本中自动提取需求标签（功能性需求/体验优化/痛点/Bug），支持自定义标签体系；标签自动关联到需求池
高亮标注与批注 P0 在转录文本上支持高亮标记、批注、@成员协作；标注内容自动归入洞察库
情感分析 P1 AI 自动分析受访者的情感倾向（正面/中性/负面），输出情感趋势图；支持按话题维度查看情感分布

3.2.3 洞察沉淀与输出 [P0]

功能项 优先级 详细描述
洞察看板 P0 聚合所有调研项目的洞察数据，按频次、情感、用户群体等维度可视化展示；支持筛选和钻取
用户画像生成 P0 AI 基于访谈数据和问卷数据自动生成用户画像（Persona），包含行为特征、目标动机、痛点、使用场景；支持手动编辑完善
调研报告导出 P1 一键生成结构化调研报告（PDF/DOCX），包含研究背景、方法论、关键发现、需求建议、附录原始数据
需求池回流 P0 调研中提取的需求标签和洞察，一键同步至产品文档模块的需求池，作为 PRD 的输入源；保留溯源链接

3.3 关键业务流程

创建调研项目 → AI 生成访谈大纲 → 执行访谈 → AI 转录 + 摘要 → 需求标签提取 → 洞察沉淀 → 回流需求池

4. 产品文档生成模块

4.1 模块概述

本模块承接调研模块的需求输入，负责产品文档的结构化撰写与管理。通过 AI 辅助生成 PRD、竞品分析报告、需求规格书等核心文档，实现从"调研洞察"到"产品定义"的智能转化。

4.2 核心功能清单

4.2.1 需求管理 [P0]

功能项 优先级 详细描述
需求池 P0 统一管理所有需求来源（调研回流、用户反馈、内部提案、竞品对标），支持列表/看板视图切换
需求详情卡片 P0 每个需求包含：标题、描述、用户故事、验收标准、来源追溯（关联调研记录/反馈单）、优先级、状态
AI 优先级建议 P0 基于 RICE 模型（Reach/Impact/Confidence/Effort），AI 综合评估需求优先级并给出排序建议；PM 可覆盖调整
需求关联与依赖 P0 支持需求之间的依赖关系设定（前置/后置/互斥/包含），变更时自动影响下游

4.2.2 PRD 文档生成 [P0]

功能项 优先级 详细描述
PRD 模板库 P0 内置多套 PRD 模板（敏捷精简版 / 标准完整版 / 详细规格版），支持自定义模板；模板包含背景、目标用户、功能清单、交互说明、非功能需求等标准章节
AI PRD 生成 P0 选入需求池中的需求后，AI 自动生成 PRD 初稿：填充功能描述、用户故事、业务流程图、验收标准；PM 审阅编辑后定稿
文档版本管理 P0 支持文档版本历史、变更对比（Diff）、回滚；关键版本支持打标签（如"评审通过"、"开发基线"）
协同编辑与评审 P0 多人实时协同编辑，支持行内评论、@提及、审批流程；评审通过后自动锁定基线版本
文档导出 P1 支持导出为 PDF / DOCX / Markdown 格式；导出时保留完整格式和批注

4.2.3 竞品分析 [P1]

功能项 优先级 详细描述
竞品信息库 P1 维护竞品列表，记录竞品的基本信息、定价策略、目标市场、核心功能
AI 竞品分析报告 P1 AI 自动生成竞品分析报告，包含功能对比矩阵、SWOT 分析、差异化建议；数据来源包括公开信息和用户录入
功能对标表 P2 结构化的功能对标矩阵，支持与需求池联动——竞品有而我没有的功能自动创建需求草稿

4.3 关键业务流程

需求池汇聚 → AI 优先级排序 → 选择需求 + 模板 → AI 生成 PRD → PM 编辑定稿 → 评审审批 → 关联原型

5. AI 原型生成模块

5.1 模块概述

本模块是 AInnoStar 的核心差异化功能。平台不自研原型编辑器，而是作为智能编排层，基于 PRD 文档中的结构化信息，通过三条并行路径生成可交互的产品原型：多 AI Agent 直接生成、集成成熟产品 MCP/Skill、挂载本地已有原型项目。无论选择哪条路径，系统均先将 PRD 解析为结构化页面描述，再分发给对应的生成引擎，大幅缩短从"需求定义"到"可视化设计"的周期。

5.2 核心设计原则

AInnoStar 不自研拖拽式原型编辑器，而是作为智能编排层，将 PRD 结构化数据转化为页面原型。支持三条并行实现路径，用户可根据团队偏好和场景灵活选择：

5.3 原型生成路径总览

路径 核心方式 适用场景 优先级
路径一 多 AI Agent 直接生成 快速出原型、探索性设计、对还原度要求不高的早期验证 P0
路径二 集成成熟产品 MCP / Skill 对生成质量要求较高、团队已使用特定设计工具生态 P0
路径三 挂载本地已有原型项目 已有 Axure 原型或前端项目，需要统一纳入管理并与 PRD 关联 P0
三条路径共享同一前置环节：无论选择哪种路径，系统均先解析关联的 PRD 文档，提取功能点、用户故事、业务流程、信息架构，生成结构化的页面描述（Prompt / 需求规格），再分发给对应的生成引擎。

5.3.1 路径一：多 AI Agent 直接生成 [P0]

通过内置的多 Agent 协作体系，将 PRD 中的结构化需求转化为可运行的 Web 页面原型。

功能项 优先级 详细描述
PRD → Prompt 编排引擎 P0 解析 PRD 文档，自动拆分为页面级 Prompt：每个页面包含布局描述、组件需求、交互逻辑、数据模型；支持用户在发送前预览和编辑 Prompt
多 Agent 固定流水线生成 P0 采用固定流水线模式，无需用户配置 Agent 编排：架构 Agent 规划页面结构与路由 → 布局 Agent 生成页面骨架 → 组件 Agent 填充表单/表格/导航等组件 → 样式 Agent 统一视觉风格；流水线按序执行，最终输出完整可运行的前端代码
技术栈与组件约束 P0 Agent 流水线遵循上游技术路线阶段确定的技术栈（前端框架、CSS 方案、组件库），确保生成代码与项目技术选型一致；技术栈未指定时默认使用 React + TailwindCSS + shadcn/ui
生成结果预览 P0 生成的页面在内置沙箱中实时预览，支持页面间跳转、基本交互演示；支持逐页面重新生成或局部修改
自然语言迭代修改 P0 用户对生成结果不满意时，可通过自然语言描述修改意图（如"把侧边栏改成顶部导航"、"增加筛选面板"），Agent 仅更新受影响部分，保留其余内容
代码导出 P1 支持将生成的完整前端代码导出为标准项目结构（含路由、组件、样式文件），可直接接入本地开发环境

5.3.2 路径二：集成成熟产品 MCP / Skill [P0]

通过 MCP（Model Context Protocol）或 Skill 接口，调用外部成熟 AI 设计工具的生成能力，在 AInnoStar 内编排、在外部工具中执行。

功能项 优先级 详细描述
MCP / Skill 集成框架 P0 提供标准化的集成层，支持接入第三方 AI 原型生成工具的 MCP Server 或 Skill 接口；MVP 阶段优先集成 Pixso（国内生态、API 成熟度高）和 Stitch（海外主流），后续按需扩展更多工具
PRD → 外部工具 Prompt 适配 P0 将 PRD 结构化数据适配为目标工具的 Prompt 格式，确保上下文（功能描述、用户故事、设计规范）完整传递；支持不同工具的 Prompt 模板管理
生成结果回流 P0 外部工具生成的原型页面（代码或预览链接）自动回流到 AInnoStar，关联到对应的 PRD 文档；支持在平台内预览和标注
工具配置管理 P1 管理各集成工具的 API Key、模型选择、默认参数；支持为不同项目/团队配置不同的生成工具偏好

5.3.3 路径三：挂载本地已有原型项目 [P0]

对于已有 Axure 原型或前端代码的团队，支持将现有项目挂载到平台，纳入统一管理并与 PRD 建立关联。

功能项 优先级 详细描述
Axure 项目导入 P0 支持上传 Axure 生成的 HTML 包（.zip），平台自动解析页面结构和导航关系，在内置预览器中还原交互效果
前端项目挂载 P0 支持接入 Git 仓库（GitHub / GitLab），将已有前端原型项目关联到产品线；平台自动识别页面路由和组件结构
静态 HTML 托管预览 P0 导入的项目自动部署到平台沙箱环境，生成可分享的在线预览链接；支持版本管理（上传新版本时保留历史版本）
PRD-原型手动关联 P0 支持将导入的原型中的具体页面与 PRD 中的功能点手动建立关联关系，实现需求-原型的双向追溯
原型页面标注 P1 支持在导入的原型页面上进行设计评审标注、评论、圈选区域；评审意见自动归档并关联到对应需求

5.3.4 通用能力：信息架构与协作 [P0]

以下能力横跨三条路径，为所有生成方式提供统一支撑：

功能项 优先级 详细描述
信息架构自动推演 P0 基于 PRD 中的功能清单和用户故事，AI 自动推演站点地图（Sitemap）和页面层级关系，作为各路径生成的输入依据
交互流程图 P0 AI 自动识别页面间的跳转关系，生成交互流程图；支持手动调整连线和新增节点
原型预览与分享 P0 统一的预览与分享入口，支持生成可交互的在线预览链接，可设置访问密码和有效期
设计评审模式 P0 支持在原型预览上直接评论、标注意见、@成员；评审意见自动归档，关联到对应需求
PRD-原型双向联动 P0 原型中的页面/组件与 PRD 功能点双向关联：PRD 修改时提示原型同步更新，原型调整时反向标记 PRD 变更
Design Token 管理 P2 团队级设计规范管理（色彩、字体、间距、圆角），路径一和路径二生成时自动遵循；支持导入品牌 Design Token

5.4 关键业务流程

关联 PRD → AI 推演信息架构 → 生成结构化页面描述 → 选择生成路径： 路径一：多 Agent 生成  |  路径二：MCP/Skill 集成  |  路径三：挂载本地项目 ↓ 原型预览与评审 → 移交开发

6. 开发跟踪与上线模块

6.1 模块概述

本模块将产品设计转化为可执行的研发任务，覆盖 Sprint 规划、任务分解、进度跟踪、质量管理和上线发布全流程。与原型模块深度集成，开发任务直接关联设计稿和需求规格，确保"所建即所需"。

6.2 核心功能清单

6.2.1 技术路线编写 [P0]

技术路线是原型生成与开发执行之间的关键衔接环节。在 PRD 评审通过后、Sprint 规划前，由技术负责人编写技术路线，确定本轮迭代的技术选型和架构决策，作为上游原型生成的约束条件和下游开发任务的指导依据。

功能项 优先级 详细描述
技术路线文档 P0 支持创建技术路线文档，关联对应 PRD；包含技术栈选型、架构方案、组件库选择、接口规范、性能指标等章节
初版组件选型 P0 在技术路线阶段确定前端框架（React / Vue / 其他）、CSS 方案（TailwindCSS / CSS Modules / 其他）、基础组件库（Ant Design / Element Plus / shadcn/ui / 自研等）；选型结果自动同步至原型生成模块，约束 Agent 生成和外部工具的输出格式
AI 技术方案建议 P1 AI 基于 PRD 中的功能复杂度、非功能性需求，自动生成技术栈推荐和架构方案初稿；技术负责人审核确认
技术路线评审 P0 技术路线完成后支持评审流程，评审通过后锁定技术选型，下游原型生成和开发任务均基于此执行

6.2.2 迭代与任务管理 [P0]

功能项 优先级 详细描述
Sprint 规划 P0 支持创建 Sprint/迭代周期，设定目标、起止时间、参与成员；支持看板/甘特图/时间线多视图切换
AI 任务拆解 P0 将 PRD 功能点或原型页面自动拆解为开发任务（前端/后端/接口/测试），估算工作量；技术负责人可调整
任务看板 P0 标准四列看板（待办 / 进行中 / 测试中 / 已完成），支持自定义列；支持拖拽切换状态、筛选、分组
需求-任务追溯矩阵 P0 每个开发任务关联到 PRD 功能点和原型页面，支持正反向追溯：点击需求查看所有关联任务，点击任务查看来源需求
工时记录与统计 P1 支持成员登记工时，Sprint 燃尽图（Burndown Chart）自动生成；迭代结束后输出 velocity 报告

6.2.3 缺陷管理 [P0]

功能项 优先级 详细描述
缺陷提交 P0 支持提交 Bug 报告，包含标题、描述、复现步骤、严重程度、优先级、截图/录屏附件
缺陷生命周期 P0 标准缺陷状态流转（新建 → 确认 → 修复中 → 验证 → 关闭），支持reopen；状态变更自动通知相关人
缺陷关联 P0 缺陷关联到具体任务、需求、原型页面；支持批量关联和批量操作
缺陷看板与统计 P1 缺陷分布看板（按模块/严重程度/责任人），缺陷趋势图；支持导出质量报告

6.2.4 上线发布管理 [P0]

功能项 优先级 详细描述
发布计划 P0 创建发布计划，关联 Sprint 完成的需求和修复的缺陷；设定发布窗口、灰度策略
上线检查清单 P0 AI 根据发布内容自动生成上线 Checklist（代码合并、数据库变更、配置更新、回归测试、监控告警）；逐项确认后允许发布
变更日志生成 P0 AI 自动汇总本次发布包含的功能变更、Bug 修复、已知问题，生成用户可读的 Release Notes
CI/CD 集成 P1 集成主流 CI/CD 工具（GitHub Actions / GitLab CI / Jenkins），构建状态实时同步到发布计划
回滚预案 P2 每次发布自动生成回滚方案（涉及回滚的代码版本、数据库脚本、配置项）；支持一键触发回滚

6.3 关键业务流程

PRD 评审通过 → 编写技术路线 → 确定组件选型 → Sprint 规划 → AI 任务拆解 → 开发执行 → 测试验证 → 上线检查 → 发布上线 → 变更日志

7. 用户反馈模块

7.1 模块概述

本模块是产品闭环的关键节点，负责上线后用户反馈的收集、分析、归类和回流。通过 AI 自动化处理大量非结构化反馈，提取有价值的产品洞察，驱动下一轮迭代优化。

7.2 核心功能清单

7.2.1 反馈收集 [P0]

功能项 优先级 详细描述
应用内反馈入口 P0 提供可嵌入产品页面的反馈组件（Widget），支持文字反馈、截图标注、评分；数据自动同步至平台
多渠道汇聚 P1 接入主流渠道的用户反馈：App Store 评价、应用市场评论、社交媒体提及、客服工单；统一汇聚到平台
NPS 调查 P1 内置 NPS（净推荐值）调查模板，支持定期自动推送；NPS 趋势图和分群分析

7.2.2 AI 智能分析 [P0]

功能项 优先级 详细描述
反馈自动分类 P0 AI 将反馈自动归类为：功能请求 / Bug 报告 / 体验问题 / 正面评价 / 其他；支持自定义分类规则
情感分析 P0 AI 分析每条反馈的情感倾向和强度，输出情感分布趋势图；异常负面波动自动告警
主题聚类 P0 AI 对相似反馈进行主题聚类（如"搜索体验差"可能包含 50 条具体反馈），提炼 Top N 高频问题
反馈-需求自动关联 P0 AI 将功能请求类反馈自动匹配到需求池中的已有需求（如已存在则追加热度），或创建新需求草稿
反馈分析报告 P1 定期生成反馈分析周报/月报，包含反馈量趋势、Top 问题、满意度变化、优化建议

7.2.3 闭环管理 [P0]

功能项 优先级 详细描述
反馈处理工作流 P0 反馈状态流转：待处理 → 已确认 → 排入需求 → 开发中 → 已上线 → 已通知用户；支持自动流转
用户通知 P1 当用户提交的反馈所关联的需求已上线时，自动发送通知告知用户"您的建议已被采纳"
反馈到调研回流 P0 高频主题自动生成调研洞察，回流到调研模块的用户画像和需求池中，驱动下一轮深度调研

7.3 关键业务流程

多渠道收集 → AI 分类 + 聚类 → 情感分析 → 关联需求池 → 排入迭代 → 上线通知 → 回流调研

8. 跨模块协作与数据流转

8.1 全局数据模型

五大模块之间的数据流转通过统一的数据模型实现，核心实体关系如下：

实体 说明 上游来源 下游消费
洞察标签 从调研/反馈中提取的结构化标签 调研模块、反馈模块 需求池

原型页面 可交互的原型设计 PRD 文档 开发任务（设计参照）

用户反馈 上线后的用户意见 外部渠道 需求池、洞察标签

8.2 全局看板 [P0]

提供项目维度的全局可视化看板，供项目负责人和团队成员了解产品整体进展：

  • 产品健康度仪表盘：NPS 趋势、反馈处理率、缺陷修复率、Sprint 交付率等关键指标
  • 需求漏斗：调研洞察 → 需求池 → PRD → 原型 → 开发 → 上线，各阶段数量和转化率
  • 迭代时间线：已发布版本的时间线视图，包含各版本的功能概要和发布日期
  • 团队工作负载：成员任务分布、工时统计、瓶颈识别

8.3 消息通知与审批 [P0]

  • 事件驱动通知：需求变更、PRD 评审、原型更新、任务分配、Bug 提交等关键事件自动推送站内消息和邮件通知
  • 审批流：PRD 发布审批、设计评审审批、上线发布审批；审批节点可自定义配置
  • 集成通知渠道：支持 Webhook 接入企业微信、钉钉、飞书等 IM 工具

9. 非功能性需求

9.1 性能要求

指标 目标值
页面首屏加载时间 < 2 秒（常规页面）
AI 生成响应时间 < 15 秒（PRD 生成） / < 30 秒（原型生成）
实时协同编辑延迟 < 500ms（CRDT 同步）
系统可用性 99.9%（SLA）

9.2 安全要求

  • 数据传输全程 TLS 1.3 加密
  • 敏感数据（访谈录音、用户信息）AES-256 加密存储
  • 支持 SSO 单点登录（SAML 2.0 / OIDC）
  • 细粒度 RBAC 权限模型，支持项目级、模块级、文档级权限控制
  • 操作审计日志，记录所有关键操作（创建、修改、删除、导出）
  • 符合 GDPR / 等保三级要求

9.3 可扩展性

  • 模块化架构，各核心模块可独立部署和扩展
  • AI 能力层抽象为统一接口，支持切换不同 LLM 提供商（OpenAI / Claude / 国产大模型）
  • 开放 API 和 Webhook，支持与企业现有工具链集成

10. 技术架构建议

10.1 整体架构

分层 技术选型建议
前端应用 React 18 + TypeScript + TailwindCSS；原型编辑器使用 Fabric.js 或 Konva.js 实现画布
后端服务 Node.js (NestJS) 或 Go (Gin)；微服务架构，各模块独立服务
数据库 PostgreSQL（关系数据） + Redis（缓存/实时协同） + Elasticsearch（全文检索）
文件存储 对象存储（S3 / OSS），存储录音文件、截图、原型资源
AI 服务层 LLM 网关统一接入多模型；语音转录接入 Whisper / 讯飞 ASR；文本分类和聚类自训练小模型
实时协同 WebSocket + CRDT（Yjs），实现文档和原型的实时多人协作
部署与运维 Docker + Kubernetes；CI/CD 使用 GitHub Actions；监控使用 Prometheus + Grafana

10.2 AI 能力架构

AI 服务作为独立层，通过统一网关接入各业务模块：

  • AI 网关：统一路由、限流、计费、模型版本管理；支持 fallback 策略（主模型不可用时自动切换备用模型）
  • Prompt 管理平台：集中管理所有 Prompt 模板，支持 A/B 测试、版本管理、效果监控
  • 向量数据库：存储调研记录、需求文档、反馈数据的 Embedding，支持语义检索和 RAG 增强
  • 自训练模型：需求分类、情感分析、反馈聚类等标准化任务使用微调的小模型，降低成本和延迟

12. 风险与应对

编号 风险项 等级 影响描述 应对策略
R1 AI 生成质量不稳定 高 PRD / 原型生成内容质量不达标，用户需要大量修改，降低产品价值 建立 Prompt 迭代机制和效果评估基线；MVP 阶段聚焦有限场景优化；提供"重新生成"和"微调"能力
R2 LLM 成本过高 中 大量 AI 调用导致运营成本不可控，影响定价竞争力 自训练小模型处理标准化任务；实施分层策略（高频简单任务用小模型，复杂推理用大模型）；设置用户调用配额
R3 模块复杂度超预期 中 五大模块同时开发导致交付周期延长、质量下降 MVP 严格裁剪功能范围；采用模块化架构允许分模块灰度上线；优先保障核心链路通畅
R4 与现有工具竞争激烈 中 Jira / Notion / 墨刀等已有成熟用户基础，迁移成本高 主打"AI 原生 + 全链路闭环"差异化；提供数据导入工具降低迁移成本；开放集成 API 而非完全替代
R5 数据安全与隐私合规 中 调研录音、用户反馈等敏感数据处理不当导致合规风险 数据加密存储与传输；支持私有化部署；企业版提供数据隔离；尽早完成等保认证
